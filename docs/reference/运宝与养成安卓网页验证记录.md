# 运宝与养成系统：Android 与局域网 Web 验证

2026-11-03 完成六项功能的服务端覆盖包、Android 和 Web 构建及实际操作验证。使用本机雷电 14.0.32.1（Android 14、x86）和独立 Chromium 浏览器，通过本机游戏服与局域网 Web 网关测试；没有使用外网穿透，本次不构建或验证 iOS。

六项功能均在“冒险”永久开放，采用本地默认规则和共用滚动操作页。实现范围、费用、概率、配置与更新步骤见 [11 运宝与养成系统](../extension/11_运宝与养成系统.md)。这是功能版本，没有复刻参考 APK 的全部界面、商业数值和附属玩法。

## 构建与环境

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File deployment/Build-Android.ps1 -Jobs 1 -SceneInspection
powershell -NoProfile -ExecutionPolicy Bypass -File deployment/Build-Web.ps1 -Jobs 1 -Emsdk tools/emsdk
powershell -NoProfile -ExecutionPolicy Bypass -File deployment/Start-Web.ps1 -SkipBuild
```

服务端改动由启动脚本调用 `Build-Admin.ps1 -ServerOnly` 编译并安装覆盖包。客户端共用同一份 C++ 代码；开发中多次构建，界面布局调整后已重新打包并安装最终 x86 APK，Web 也重新构建并在局域网重新载入。资源版本 **1.80.0**。Android 同时生成通用包；实际安装验证的是 x86 专用包，最低及目标 SDK 均为 21。

本机验证地址为 `http://192.168.30.101:18084/`，只对本次网络有效。换电脑应使用启动脚本输出的网址。游戏 TCP、资源 HTTP、数据库分别使用本部署实际选择的 25525、18083、13307 端口，不要求其他电脑固定使用这些端口。

测试角色为 `NRBAC01`（角色 4，Android）和 `NRBAC02`（角色 5，Web）。通过现有管理接口各发送一次测试物资传书，并由客户端实际领取；没有通过修改数据库钱包或进度绕过付费和成长条件。协议检查也使用正常账号认证后的游戏连接，账号凭据保存在本机私有目录。

## 协议与资产检查

除了真实 UI 操作，另执行 22 组协议检查，其中每组包含多个断言：

- 运宝：相同开始请求重放、未完成不能领取、加速费用仅扣一次、领取只生成一次传书、完成后不能重复领取。
- 装备：已穿戴实例不能分解，淬炼实际增加 5 点攻击，进阶实际改变战斗属性，同编号重试不再扣费，不存在的实例不能养成。
- 奥义：替换保持原实例 ID，进化后的实际战斗技能数值增加，相同请求重放不扣费，额外奥义不能走天生替换。
- 船员：不足 3 阶不能超进化，进化和超进化实际提高战斗属性，重生恢复本页成长前的属性，重复请求只生成一份返还传书。
- 潜能：预览重试只消耗一次药剂，未处理预览不能重抽，放弃不扣潜能，保留精确增加预览对应属性并消耗潜能，不能重复保留。
- 船舱：拒绝上阵船员、锁定舱位和重复安置；安置、舱位升级与船体强化实际改变全队属性；船体首次购买只扣一次，离舱不删除卡牌。

另外检查了按钮响应内的 `choice/enabled` 字段：目标奥义、目标舱位传递正确；未达条件的超进化、已穿戴装备分解按钮禁用。通过原有换人协议将舱内船员上阵，确认自动离舱且两张卡牌均保留，再恢复原阵容。没有模拟一个不存在的服务端实现或直接调用客户端按钮回调来代替实际交互。

## 保存和重启

记录角色扩展进度、钱包、幂等回执、传书、奥义、装备、船员、背包、战斗快照九组数据，停止并重新启动本部署。重启前后的持久化记录一致；两个账号重新认证后，六项玩法均读回对应角色的进度。重放最初的装备淬炼和运宝开始请求，即使附带旧进度、旧规则版本，也返回原操作结果，没有新增扣费、奖励或进度。

当时角色 4、5 的扩展版本分别为 55、32。角色 4 的训练累计生命 +4、攻击 +2，剩余潜能 58；角色 5 保留意志 +4，剩余潜能 59，并有一份尚未处理的意志 +2 预览。该预览在重启后保持不变，没有重新随机或再次扣药剂。两端还分别重新进入船舱和训练页面检查实际显示。

停服保存另外使用真实远航奖励做验证，结果记录于本机 `graceful-stop-wallet.json` 和 `graceful-stop-verified.json`。停止脚本使用实例私有凭据请求正常 JVM 退出，等待游戏保存结束后再关闭数据库；错误凭据返回 401，游戏继续运行。最终又检查了停止后的完整快照与下一次启动的数据一致。

## 联调中修复的问题

1. **按钮参数丢失**：服务端 JSON 数组插入对象时会复制，原来向插入前对象追加 `choice/enabled` 没有进入响应。改为修改数组内对象后，天生奥义替换、指定舱位解锁及禁用条件均通过真实 UI 重测。
2. **Web 提示重复整包更新**：资源准备脚本原来固定写旧版本号；现在按发布清单选择实际打包版本，新的 Web 包与服务端均为 1.80.0。
3. **布局、导航及文字**：按旧 CCB 的实际缩放和裁剪范围排版，避让原底部导航；中文使用系统字体，刷新与传书固定页头，长列表可滚动。
4. **奖励缓存未刷新**：新增奖励后主动刷新原传书列表，解决已打开过传书页的角色暂时看不到新奖励的问题。
5. **成长刷新请求缓冲区不兼容**：复用原背包/阵容响应时使用可读请求缓冲区，避免直接缓冲区的 `array()` 异常。
6. **潜能规则校验误拒绝合法道具 ID**：费用、倍率与模板 ID 分开校验，允许已有药剂模板 1502001。
7. **停止脚本直接结束 Java**：新增只监听回环地址、使用实例专属凭据的停止入口，停止接收新请求，执行原停服保存；提交结果不明的角色在定时及停服保存时均受到保护。

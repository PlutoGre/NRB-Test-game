# 首页与养成界面 Android、Web 验证记录

验证日期：2026-11-04。本次实际编译、部署和操作的是本地项目；参考 APK 的画面不作为验证结果。

## 环境及产物

- 本机 Windows；雷电 Android 14 x86，900 × 1600。安装并运行 `outputs/android/DreamOnePiece-emulator-x86-debug.apk`。
- 通用包 `outputs/android/DreamOnePiece-debug.apk` 已编译，包含 armeabi、armeabi-v7a、x86；本轮未在 ARM 真机安装验证。
- Web 使用本机 Chrome 独立测试配置，通过 CDP 鼠标操作实际 Canvas/WebGL 页面；以局域网地址访问，不使用外网穿透。构建目录 `outputs/web/`，本次地址 `http://192.168.30.101:18084/`。地址取决于部署电脑 IP 和实际端口。
- 先备份数据库，再构建 Java 服务端覆盖层并重启，发布 1.81.0 养成资源及 1.82.0 首页资源。备份位于本机 `runtime/server/backups/`。
- 两端分别使用已有测试角色；操作会正常消耗这些角色的测试贝里、钻石和材料。未清空玩家数据库。
- Android 本次启用可选的只读场景检查用于定位控件；玩法均通过真实点击执行，没有用接口请求代替 UI 操作。

复现构建（仓库根目录 PowerShell，先部署服务端和相应工具链）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File deployment/Build-Android.ps1 -Jobs 2 -SceneInspection -Offline
powershell -NoProfile -ExecutionPolicy Bypass -File deployment/Build-Web.ps1 -Jobs 2 -Emsdk tools/emsdk
```

`-Offline` 只适合工具已齐备的电脑；新电脑先按构建文档准备工具。常规包无需加 `-SceneInspection`。

## 本次发现并修复的问题

1. `MainPage` 引用等待状态缺少头文件，导致编译失败：补齐声明依赖。
2. 原首页 CCB 根节点尺寸为零，新界面首次构建可能没有可用边界：等待挂入场景，以原角色栏及底部导航计算可用范围；调整顶部及快捷文字位置。
3. 养成页确认点击中立即删除重建节点，旧触摸分发器仍在遍历这些节点，导致 Android 原生崩溃、Web 越界冻结：点击只排队，下一帧再处理；前往传书后立即返回，避免使用已销毁页面。
4. 旧 JsonCpp 会将 null 视为可转换的 object/array，出现空对象图框等展示异常：展示数据增加显式 null 检查。
5. 按钮文字未居中、九宫格金边过厚：调整对齐、缩放及边框保留区域。

修复后重新构建和安装，并重复上述操作。最终 Android 本地进程 logcat 未见 `FATAL EXCEPTION` / `Fatal signal`；本轮 Chrome 未见运行时异常。Web 首次装载资源时有 Emscripten dependency 等待输出，属于启动加载日志，未当作崩溃。

# 管理工具发奖与界面修复实测（2026-11-02）

## 复现与修复

在当前 Windows 电脑，实际打开 `NRB游戏管理.exe`，登录后向本地角色 `NRBQA02` 发送 7 钻石。旧版在发送前查询批次时报错：

```text
org.hibernate.MappingException: No Dialect mapping for JDBC type: -1
    at com.oldmountain.dzm.admin.AdminServer.findBatch(...)
```

当时 `rewards` 没有新增记录，批次表也没有记录，因此重新登录或继续等待不能收到传书。

`AdminServer.findBatch()` 和 `history()` 对 `details` 增加 `Hibernate.STRING` 标量映射，兼容 MariaDB `MEDIUMTEXT` 与项目旧 Hibernate。数据库结构、账号和已有奖励记录不需要重建。

实际领取混合附件时，又确认旧客户端只识别带品质的卡牌、影子、装备和奥义类型。`RewardServices.getSysMsgInfo()` 现在只对管理传书转换显示类型；残章显示所属奥义 ID，领取仍使用数据库中的原类别和真实模板 ID。已有 APK 无需重打包。

## 界面检查

原登录区固定为94像素，但内部控件实际需要更多高度，状态文字被下方标签页覆盖。已改为自适应行高、随窗口拉伸的输入框、可换行说明、自动适配类别/ID列，以及可滚动的完整表单和结果框。发放清单保留至少100像素高度，不再被压成一条线。

使用实际管理窗口类完成登录，分别检查普通字体及1.25/1.5倍放大字体。普通字体检查1000×720窗口；放大字体检查1280×850窗口。可见标签高度检查均无截断，历史页均成功显示4条记录；小窗口滚动后可完整访问发送按钮。这里的放大字体测试不等于实际切换 Windows 系统 DPI。

一次旧测试脚本把需要调用进程内存的标签控件消息发送到了另一进程，触发了 `comctl32` 异常；已删除该脚本用法。后续用同一窗口类的正常标签切换、按钮操作完成历史页验证，没有把脚本错误计为业务程序通过或未修复的客户端问题。

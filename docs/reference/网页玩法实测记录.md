# Web 客户端玩法实测（2026-11-02）

本次实际编译并运行原 C++/Lua 游戏，通过浏览器画布点击、拖动、中文输入、建角和战斗验证。没有用接口模拟战斗结果。当前已实现的主要流程可以游玩，但原项目缺失的玩法仍不能使用。

## 环境与测试角色

- Windows 本地构建，Emscripten 3.1.74，653 个游戏、引擎和协议源文件，产物位于 `outputs/web`。
- Playwright 驱动真实 Chromium 156.0.8078.4，WebGL 使用 SwiftShader；验证 640×960 和 390×844 两种浏览器窗口。手机尺寸窗口验证不代表已测试 iPhone Safari 或 Android 真机浏览器。
- 使用当前 `runtime/server` 的 Java、MariaDB 和 WebSocket 网关，网页端口为本次实际选择的 18084。其他电脑以启动窗口显示的地址为准。
- 独立创建“网页验收”角色，区服“男人帮1区”。先按正常新手流程测试，再通过已有管理工具接口只给该角色发测试经验、船员及道具，并在游戏界面领取。没有向其他角色群发。
- 为覆盖高等级入口，测试角色升至 37 级；后续通过背包实际使用葡萄酒培养上阵船员。测试资源不属于新玩家默认奖励。

## 本次修复

1. **画面可见但点击无效**：SDL2 的浏览器输入绑定依赖 `#canvas`，原宿主页使用 `#game`。统一画布 ID，鼠标点击和拖动进入原游戏输入系统。
2. **发经验后等级与服务端不同步**：管理传书原来只增加经验。改用正常升级流程，同步等级、升级奖励及阵位；由于旧升级通知一次只带一个新阵位，连升多级后另发完整阵容。
3. **上阵失败后无法重试**：请求失败、超时或发送失败时恢复确认状态，离开页面移除监听。新包中故意跨过前面的空阵位，连续两次点击确认，服务端均收到请求并按规则拒绝；修复前第二次点击不会发送请求。随后按顺序上阵成功。
4. **经验酒消耗后经验可能丢失**：葡萄酒、朗姆酒没有把修改的船员登记到保存队列，阵容战斗属性与卡牌经验可能保存不一致。补齐登记，并按每名船员单独计算等级上限，避免前一名船员达到上限影响后续经验。实际使用两种酒，触发原有保存队列，核对数据库后重启并确认保留。
5. **个别敌人语音文件缺失**：凯多和奥兹的卡表引用 `sound/man011.mp3`，现有文件为 `man11.mp3`。补充同内容的兼容文件名，保留原有卡表和声音资源。

新增的 Web 场景快照只读取可见节点、文字及坐标，用于定位真实鼠标操作；不提供发道具、跳关或伪造战斗结果的功能。

## 保存、产物与未覆盖项

测试前保存了数据库快照。临时黑胡子配置恢复后核对了原文件 SHA-256，并重新进入页面确认恢复默认倒计时。经验酒回归测试通过现有游戏主循环调用保存队列后重启，未把“浏览器刷新仍在缓存中”当成持久化成功。普通游戏状态仍按原服务端保存周期落库，本文没有把强行结束 Java 进程视为安全保存方式。

原始截图、浏览器日志、发放批次、数据库对比和浏览器测试会话保存在本机 `outputs/web-qa`，不提交包含会话和玩家数据的文件。本文引用的截图另存入文档目录。SDK、编译缓存及 `outputs/web` 不提交；换电脑应重新构建或下载 Actions 产物。

未覆盖所有卡牌、装备数值、全部远航章节、长期活动排期、完整新服生命周期、多人并发、充值，以及手机真机浏览器。原源码缺失的运宝、All Blue 和转盘需要补齐相应资源、页面、协议和服务端逻辑，不能据此次 Web 适配认定可用。

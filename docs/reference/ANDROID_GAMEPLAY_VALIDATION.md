## 服务器选择无响应的处理

在此雷电环境，ARM 包经 `libhoudini` 转译时，GL 线程卡在原生加载/渲染过程中，触摸事件虽到达 Java 层却无法执行。新增原生 x86 编译后，同一实例可以选择服务器、进入游戏并完成上述操作。

- NDK 同时构建 `armeabi`、`armeabi-v7a`、`x86`；补齐 protobuf x86 原子操作实现。
- ARM 专用的旧 UDID 库不参与 x86 构建。
- 登录和版本检查结果通过 GL 线程通知原生游戏，避免平台回调与 Cocos 场景状态并发修改。
- 一键打包额外生成 `DreamOnePiece-emulator-x86-debug.apk`，排除依赖库中旧支付 SDK 的 ARM 文件，并校验专用包只含 x86 游戏库。
- 实测通用包普通安装时雷电选择 ARM；专用包普通覆盖安装后为 `primaryCpuAbi=x86`、`cpuAbiOverride=null`，无需 `--abi` 参数。

测试中切换 ARM/x86 包曾遇到模拟器图形进程异常，需要完整重启雷电恢复。没有把临时关闭硬件加速的实验配置保留到交付版本。正常硬件加速下已完成上述游玩、重新登录、输入框取消和前后台切换；不承诺所有模拟器图形驱动组合均兼容。

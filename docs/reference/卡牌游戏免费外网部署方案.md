# 卡牌小游戏免费外网部署方案

> NRB-Test-game 项目集成入口：[本项目外网部署说明](EXTERNAL_DEPLOYMENT.md)。本项目使用裸 TCP，需要新增 WebSocket 网关及 iOS 适配，不能直接套用本文的 HTTP 游戏接口示例。相关代码现已加入，尚未运行联调或构建验证；项目操作请优先按集成文档执行。下文保留为通用方案参考。

更新时间：2026-10-29。

## 1. 使用场景与方案结论

本方案面向个人开发学习：家里的普通电脑运行游戏服务端，最多约 4～5 台手机通过互联网连接，客户端主要为 iPhone。游戏为卡牌小游戏，交互数据量小，不要求全天在线。

约束条件：

- 使用免费工具与服务，不租用云服务器、不购买域名。
- 不申请运营商公网 IPv4，不依赖路由器端口映射。
- 手机可使用流量或其他地方的 Wi-Fi，不要求与电脑处于同一局域网。
- 手机只运行游戏即可，无需额外安装组网或 VPN 软件。

选择 **Cloudflare Quick Tunnel + 家庭电脑上的 HTTP 服务端**。客户端访问临时 HTTPS 域名，Cloudflare 通过电脑主动建立的隧道转发到本地服务。

Quick Tunnel 免费且无需 Cloudflare 账号或自有域名，定位为开发测试服务。每次新建隧道会分配新的域名，无可用性保证；当前限制为最多 200 个正在处理的请求，不支持 SSE。200 是请求数，并非玩家数。[官方使用说明](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)

这些容量限制通常不会成为本场景的主要障碍；实际可用性仍需用电脑宽带和各手机网络验证，尤其不能预先保证中国大陆不同运营商网络的访问效果。

> 本文是可迁移到其他项目的部署与接入说明，尚未针对具体游戏框架完成适配。文中接口、端口和配置名称均为示例，不代表目标项目已经实现。

## 2. 网络结构

```text
iPhone 游戏客户端
    |
    | HTTPS / 可选 WSS
    v
https://<本次分配的域名>.trycloudflare.com
    |
    | Cloudflare Tunnel
    v
家庭电脑上的 cloudflared 进程
    |
    | HTTP，经电脑本机回环地址访问
    v
http://127.0.0.1:8080
    |
    v
游戏服务端 -> 本地数据库或存档文件
```

- 服务端与 `cloudflared` 默认运行在同一台电脑上。
- 手机连接 Cloudflare 的 HTTPS 地址；电脑本地 HTTP 服务无需自行配置公网证书。
- 同机部署时，服务端可以只监听 `127.0.0.1`，无需为了隧道改成 `0.0.0.0`。
- 路由器不需要开放入站端口；电脑需要能够向 Cloudflare 建立出站连接。[连接原理](https://developers.cloudflare.com/tunnel/concepts/)
- 数据库留在电脑上，由游戏服务端访问，不单独发布数据库端口。

本文以直接运行在 Windows 主机上的服务端为例。如果服务端使用 Docker、WSL 或虚拟机，必须先确保 Windows 主机能够访问其发布的 HTTP 端口，再启动隧道；不同环境中的 `127.0.0.1` 不一定指向同一处。

## 3. 游戏项目需要具备的能力

### 3.1 服务端

优先保留目标项目已有框架、接口与存储方式，不需要因为采用本方案更换技术栈。

最低接入条件：

1. 能以 HTTP 提供游戏接口，并明确启动命令、监听地址和端口。
2. 提供一个无需登录的轻量健康检查接口，例如 `GET /ping`，用于判断链路是否打通。
3. 游戏接口通过登录令牌或测试会话识别玩家，房间成员和操作权限由服务端校验。
4. 游戏规则、回合顺序、手牌归属和胜负由服务端判定；返回给每名玩家的数据应隐藏其他玩家不可见的手牌等信息。
5. 实时房间状态设置为不缓存，例如返回 `Cache-Control: no-store`。
6. 不向外发布调试控制台、数据库管理页、任意文件读取接口等与游戏无关的入口。

建议的健康检查响应：

```json
{"ok":true}
```

以下接口只用于说明分工。目标项目已有接口时直接复用，不必照搬命名：

| 用途 | 示例接口 | 备注 |
| --- | --- | --- |
| 健康检查 | `GET /ping` | 无敏感信息 |
| 登录或建立测试会话 | `POST /api/session` | 返回玩家身份和令牌 |
| 创建房间 | `POST /api/rooms` | 返回房间标识 |
| 加入房间 | `POST /api/rooms/{roomId}/join` | 校验加入条件 |
| 获取当前玩家可见的房间状态 | `GET /api/rooms/{roomId}` | 适用于轮询 |
| 提交游戏操作 | `POST /api/rooms/{roomId}/actions` | 服务端校验合法性 |

存储可沿用现有数据库。尚未选型时，SQLite 可作为学习阶段的起点。测试房间状态可以先保存在内存，但应明确：进程重启会丢失内存状态，需要持久保存的账号和进度应写入存储。

### 3.2 iOS 客户端

核心要求是**服务器基础地址可配置，不写死临时域名**。

建议在开发设置或连接页提供：

- 服务器地址输入框，接受 `https://……trycloudflare.com`。
- 保存地址功能，重启 App 后仍保留。
- 测试连接按钮，请求 `/ping`。
- 明确显示当前连接地址和错误原因，例如超时、服务不可达或登录失效。

接口地址统一由一个网络配置入口拼接：

```text
基础地址：https://<本次分配的域名>.trycloudflare.com
接口路径：/api/rooms
完整地址：https://<本次分配的域名>.trycloudflare.com/api/rooms
```

接入细节：

1. 去除输入首尾空白，统一处理末尾斜杠，避免生成重复路径或 `//`。
2. 手机不要填写 `localhost`、`127.0.0.1` 或电脑的 `192.168.x.x` 地址作为本方案的外网地址。
3. 地址使用 HTTPS，保留系统正常证书校验。不要为了本方案关闭证书校验或全局放开明文 HTTP。
4. 切换服务器地址时，停止旧轮询、取消旧请求、关闭旧长连接；旧会话令牌不发送给新地址，避免不同服务的数据混用。
5. 请求超时可以先取 10～15 秒，随后根据实测调整，不在界面主线程等待网络结果。
6. 从后台回到前台、网络切换或连接恢复后，重新拉取房间状态，不依赖后台连接一直保持。

如果客户端是网页或 WebView 中的网页，还应按实际来源配置 CORS。原生网络请求通常不受浏览器 CORS 机制限制；Safari 能打开接口也不等于游戏的鉴权和请求处理已经正确。

## 4. Windows 电脑部署步骤

### 4.1 启动游戏服务端

按照目标项目的 README 启动服务端，并确认本地入口。例如：

```text
http://127.0.0.1:8080
```

这里的 `8080` 是示例。项目使用其他端口时，后面的隧道命令也要同步替换。

部署者可先用电脑浏览器访问：

```text
http://127.0.0.1:8080/ping
```

预期得到约定的健康检查响应。如果本机访问失败，先排查服务端启动和路由，不进入隧道步骤。

### 4.2 下载 cloudflared

从 [Cloudflare 官方下载页](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/downloads/)进入 Windows 下载入口，选择适合电脑架构的可执行文件。常见 Intel/AMD 64 位电脑选择 Windows 64-bit 可执行文件。

可将下载文件重命名为 `cloudflared.exe`，放到一个固定工具目录。下面以 `D:\tools\cloudflared` 为示例路径，请替换为实际位置。

本方案直接运行可执行文件，不要求安装为系统服务。

### 4.3 启动免费临时隧道

在工具目录打开 PowerShell，执行：

```powershell
.\cloudflared.exe tunnel --url http://127.0.0.1:8080
```

保留此窗口运行，从日志中复制本次生成的 HTTPS 地址，例如：

```text
https://<本次分配的域名>.trycloudflare.com
```

以上域名为占位示例，必须替换为日志中的真实地址。Quick Tunnel 的基本操作见 [官方说明](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)。

### 4.4 用 iPhone 验证外网访问

1. 关闭 iPhone 的 Wi-Fi，改用蜂窝网络，确保不是在验证同一局域网访问。
2. 在 Safari 中打开本次临时域名下的 `/ping`。
3. 确认响应正常后，把临时域名填入游戏的服务器地址设置。
4. 先用一台手机完成登录和进入房间，再增加到 4～5 台进行交互验证。

### 4.5 测试结束后关闭

在运行 `cloudflared` 的窗口按 `Ctrl+C`，再按项目方式停止游戏服务端。停止隧道后，临时公网入口将不可用。

## 5. 卡牌交互方式

### 5.1 起步采用 HTTPS 请求与轮询

如果项目尚未实现实时通信，可以先采用：

- 创建房间、加入、准备、出牌：HTTPS 请求。
- 等待其他玩家操作：定时查询房间状态。
- 游戏在前台时，轮询间隔可从 1～2 秒开始；离开房间或进入后台后停止。
- 上一次轮询未结束时不再启动下一次，网络失败时逐步延长间隔。

4～5 个客户端按这个频率查询、服务端及时响应时，通常不需要为数据量引入更复杂的通信架构。

获取状态失败后可以重试。出牌、领取奖励等会改变状态的请求不能直接无限重试：建议携带唯一操作 ID，由服务端识别重复请求；如果项目暂未实现去重，超时后先查询最新状态再决定下一步。

### 5.2 需要主动推送时使用 WebSocket

已有 WebSocket 的项目可以继续使用，通过公网域名的 `wss://` 地址连接。例如：

```text
wss://<本次分配的域名>.trycloudflare.com/ws
```

`/ws` 为示例，按实际路由替换。基础地址变化后，WebSocket 地址也应同步更新。

需要实现心跳、断线重连、会话校验以及重连后重新获取房间状态。Cloudflare 支持 WebSocket，但连接仍可能因网络变化或平台维护而中断。[WebSocket 官方说明](https://developers.cloudflare.com/network/websockets/)

Quick Tunnel 不支持 SSE；如果所用框架会自动选择通信方式，应确认选择 WebSocket 或轮询，而不是依赖 SSE。[Quick Tunnel 限制](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)

本方案的公开入口按 HTTP/HTTPS/WebSocket 使用，不作为任意自定义裸 TCP 或 UDP 游戏协议的转发入口。

## 6. 每次开发测试的流程

1. 电脑联网，启动服务端。
2. 本机访问 `/ping`，确认服务端可用。
3. 启动 `cloudflared`，复制本次临时域名。
4. 把地址发给参与测试的人，由各自在游戏中更新。
5. 手机测试连接后进入房间。
6. 测试期间保持电脑唤醒、服务端进程和隧道进程运行。
7. 测试结束关闭隧道和服务端。

如果只重启游戏服务端而隧道仍在运行，通常无需更换域名；但内存房间与会话是否保留取决于项目实现。

## 7. 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 本机 `/ping` 访问失败 | 服务端是否启动、端口是否一致、是否存在该路由 |
| 公网访问返回 502 | 隧道进程是否能访问本地服务，目标协议和端口是否正确 |
| 公网访问超时或域名无法解析 | 隧道是否建立、手机网络是否能访问该域名、是否复制了旧地址 |
| 返回 404 | 接口路径和 API 前缀是否正确，不要把路由不存在当作网络故障 |
| 返回 401/403 | 游戏会话、令牌、房间权限或代理访问限制，不能只归因于隧道 |
| 返回 429 | 检查轮询重叠、无限重试和服务自身限流；Quick Tunnel 也有并发请求限制 |
| Safari 能访问，但游戏失败 | 游戏基础地址、路径拼接、证书错误、令牌和响应解析 |
| 请求返回 HTML 登录页而非 JSON | 是否误用了需要浏览器交互的访问认证，或请求落到了错误页面 |
| WebSocket 连接不上 | 是否使用 `wss://`、路由和鉴权是否一致、服务端是否支持升级连接 |
| 其他人看到旧状态 | 客户端缓存、服务端缓存头、旧轮询和房间版本是否正确处理 |
| 电脑锁屏或合盖后掉线 | 是否进入休眠、网络是否断开，开发测试期间保持唤醒 |

同机回环地址部署通常不需要放行公网入站端口。若隧道无法建立，检查出站网络策略；Cloudflare Tunnel 连接使用出站端口 `7844`，QUIC 使用 UDP，HTTP/2 使用 TCP。[防火墙说明](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/configure-tunnels/tunnel-with-firewall/)

Quick Tunnel 的邮件验证功能要求交互式浏览器会话，本方案不启用该功能；游戏接口使用项目自身的鉴权方式。[官方说明](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)

临时域名不是访问密码，知道地址的人可以尝试请求接口。学习阶段也应校验玩家身份和操作权限；日志记录必要错误与操作结果，避免输出完整令牌、密码和其他玩家的隐藏数据。

## 9. 备用方案

若 Quick Tunnel 在实际网络下不可用，或频繁更换域名影响开发，可以改用 Tailscale，让电脑和手机加入同一虚拟私有网络。它需要在每台 iPhone 上额外安装客户端并允许 VPN 配置。[iOS 安装说明](https://tailscale.com/docs/install/ios)

采用该方案后，服务端需监听 Tailscale 地址或可被该网络访问的接口，调整电脑防火墙，并重新确认客户端访问方式；不能直接沿用本文仅监听 `127.0.0.1` 的配置。

Tailscale 的免费额度、账号限制及网络可用性，以迁移时的 [官方定价](https://tailscale.com/pricing)和实测结果为准。

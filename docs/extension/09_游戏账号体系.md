# 游戏账号、注册和存档绑定

[返回扩展指南](扩展指南索引.md)。本次新增账号体系，覆盖当前自建渠道的 Android、iOS 和 Web 客户端。代码已接入；本次按项目约定只做源码、路径和差异检查，**未执行编译、部署、测试或模拟器验证**，旧 APK、IPA 和 Web 包仍需更新。

## 玩家使用

1. 服务端启动成功后打开客户端。首次登录显示账号、密码输入窗口；没有账号时点“注册账号”。
2. 注册填写账号、密码、确认密码。账号为 **3–32 位英文字母或数字，不区分大小写**；密码为 **6–64 个字符**，区分大小写。
3. 服务端验证成功后才能进入“男人帮1区”。首次使用该账号进入区服时，沿用游戏原有的新建角色和新手流程。
4. 登录成功后，本机记住账号和不透明的登录凭证。下次打开先向服务端恢复登录，不必重复输密码；凭证到期或被撤销时重新输入。凭证有效期 30 天，恢复登录时续期。
5. 登录页右上角有“账号名 | 切换账号”。点击后清除本机旧凭证并进入账号密码窗口。Web 下载前的启动页面也有切换按钮。
6. 更换手机、重装客户端、清理浏览器数据或临时隧道换网址后，输入原账号密码即可找回**同一服务端数据库中的角色**。Android、iOS、Web 使用同一个账号 UID，不再按渠道或设备另建身份。

切换按钮位于进入游戏前的登录页。已经进入玩法页面时先关闭并重新打开游戏，再切换账号，避免旧角色的客户端内存缓存混入新账号。服务器仍沿用原来的重复在线处理，同一账号不应在多端同时游玩。

`op_root / hy1212` 是 Windows 管理工具的账号，不是玩家账号；玩家需另外注册。当前没有接入短信、邮箱找回或第三方渠道账号。

## 已有部署如何更新

在仓库根目录执行 `git pull` 后：

1. 双击 `停止服务.cmd`，完整停止本实例，包括已有的 Web 和 iOS 隧道入口。
2. 双击 `启动服务.cmd`。脚本按源码指纹重新生成服务端覆盖 JAR，然后升级账号数据。
3. **按本项目所有者的决定，旧游客不迁移。** 首次升级启动时，脚本先导出完整数据库备份，再删除未绑定注册账号的测试角色、账号映射、背包、卡牌、装备、奥义等归属记录；已注册账号的 UID 会受到保护。清理发生在 Java 游戏服加载玩家缓存之前，不会每次启动都重复执行。
4. 备份位于 `runtime/server/backups/onepiece-*.sql.gz`，含配套 `.sha256`；完成记录位于 `runtime/server/private/account-system-v1.json`。备份或清理失败会停止启动，不会绕过认证继续使用游客模式。不要为了重复清理手工删除完成记录。
5. 重新打包客户端。Android 按 [客户端打包流程](../客户端打包流程.md) 生成并安装新 APK；iOS 重新运行 Actions 构建并签名安装新 IPA；Web 按 [网页流程](../网页客户端流程.md) 重新构建再启动。`启动网页外网.cmd` 也会识别缺少账号协议的新旧 Web 包并触发构建。

这次包含 Java 登录校验、C++ 登录包和平台窗口，**只更新服务端或只替换图片资源均不能完成升级**。旧客户端携带设备游客标识和固定密码，更新后的游戏服会拒绝登录。原有管理员 EXE 的管理协议保持兼容。

本次代码修改没有执行上述步骤，没有删除当前电脑数据库中的角色，也没有替换现有安装包。

## 服务端保存结构

新增两张表，由服务端启动时创建，不需要重新导入 `dzm.sql`：

| 表 | 关键内容 | 说明 |
|---|---|---|
| `nrb_accounts` | `uid`、`username`、`salt`、`passwordHash`、`iterations`、`createdAt` | 账号名唯一；密码使用独立随机盐和 PBKDF2-HMAC-SHA256 摘要，120000 次迭代 |
| `nrb_account_sessions` | `tokenHash`、`uid`、`expiresAt`、`createdAt` | 数据库只保存凭证的 SHA-256 摘要；支持重启后恢复登录和单设备退出 |

服务端分配稳定的 `acct_` 加 32 位十六进制 UID。原有存档继续使用：

```text
账号名/密码 → nrb_accounts.uid
                        ↓
             mapping.puid → mapping.gameid
                                   ↓
                             player.id
                                   ↓
                 disciple/equip/skill/bag 等 playerid
```

账号名不是游戏角色名，改设备也不会改变 UID。发物品仍在管理工具中按游戏内角色名定位。不要用账号名替换 `player.puid`，不要修改 `mapping.gameid` 来“找回角色”，也不要手工写密码摘要。

账号和角色属于当前数据库实例。仅 `clone` 源码到另一台开服电脑不会带走已有账号或角色；需要按 [服务端备份恢复](../reference/服务端部署与迁移参考.md) 迁移整个数据库。备份中的账号表和角色表必须一起迁移。

## 请求与认证链路

| JSON POST | 输入 | 成功响应 |
|---|---|---|
| `/account/v1/register` | `username`、`password`、`confirmPassword` | `ok`、`uid`、`username`、`token`、`expiresIn` |
| `/account/v1/login` | `username`、`password` | 同上 |
| `/account/v1/resume` | `token` | 同上，恢复并续期 |
| `/account/v1/logout` | `token` | `ok: true`，撤销该设备会话 |

HTTP 400 表示输入不合法、账号重名或请求频率超限；401 表示账号密码错误或凭证失效；503 表示服务端未准备好。客户端会展示错误并允许重试，网络异常不会创建游客身份。

账号接口复用当前资源入口的地址，不新增手机需要填写的端口：

- Android / iOS 局域网：从 `SeverConsts` 当前 `rootAddress` 提取资源服务的 origin，由 `resource_server.py` 转发。
- iOS 外网：使用连接页选中的 HTTPS origin，并继续携带该服务器邀请码，由 `websocket_gateway.py` 转发。
- Web：同源 `/account/v1/*`，由 `web_client.py` 转发。成功认证后签发 HttpOnly Cookie，用来保护 WebSocket 和资源入口。
- Java 账号 HTTP 接口与管理 API 共用本机监听端口，仅绑定 `127.0.0.1`。公开代理只允许上述四个账号动作，不能转发 `/admin/v1/*`。

进入游戏及断线重连的 `OPLogin.puid` 携带服务端 UID，`OPLogin.pwd` 携带登录凭证。复用原 Protobuf 字段，无需重新生成协议代码。Java `LoginHandler` 在加载/新建角色之前再次查询会话并验证 UID；认证失败返回状态 **6**，不会根据客户端自行提供的 UID 读取存档。

`PacketHandler` 同时阻止未认证连接发送普通玩法请求；旧激活码流程只允许操作已认证账号自己的 UID。无需角色数据的心跳仍可在登录前使用。

登录页遇到状态 6 会回到账号输入；玩法中重连遇到状态 6 会停止自动登录并提示重启游戏。登录包的调试日志不再输出凭证，原 `player.password` / `mapping.passwd` 列只保存兼容占位符。

## 本地保存与代码入口

| 层次 | 维护入口 |
|---|---|
| 账号表、密码摘要、会话持久化 | `server/source/src/com/oldmountain/dzm/admin/AccountService.java` |
| Java HTTP 输入输出 | 同目录 `AccountHandler.java`，由 `AdminServer` 注册 |
| 游戏连接认证 | `server/source/src/com/oldmountain/dzm/packethandler/LoginHandler.java` |
| 覆盖 JAR 的打包清单 | `deployment/admin/source_inputs.py` |
| 停服后的首次游客清理 | `deployment/account_migration.py` |
| 公开 JSON 转发、长度限制、HTTP 分块读取 | `deployment/account_proxy.py` |
| 局域网资源与账号入口 | `deployment/resource_server.py` |
| Android 登录/注册窗口 | `client/source/Game/proj.android/src/com/youai/dreamonepiece/platform/defaultplatform/AccountLogin.java` |
| Android 平台结果 | 同目录 `PlatformDefaultLoginAndPay.java`；新增类同时列入 `antbuild/prepare_channel.py` |
| Android URL 桥接 | `client/source/Game/proj.android/jni/GameMain.cpp` |
| iOS 窗口、请求、Keychain | `client/ios/native/LocalPlatform.mm` |
| Web 窗口、凭证缓存 | `client/web/shell/accounts.js`、`index.html` |
| Web 原生平台桥 | `client/web/native/LocalPlatform.cpp` |
| 三端登录包、切换按钮与过期处理 | `client/source/Game/Classes/{LoadingFrame,LoginPacket,PackageLogic,PacketManager,SeverConsts}.*` |

Android 使用应用私有 SharedPreferences 保存账号名和凭证，已关闭当前 APK 的系统应用备份；iOS 使用仅本机可访问的 Keychain；Web 保存于当前网站的 localStorage。三端均不把密码写入本地配置。公共外网入口使用现有 HTTPS；局域网直连保持现有 HTTP 方式。

## 后续人工验收

本次没有运行以下检查，供重新打包后逐项确认：

1. 首次启动弹窗；非法账号、短密码、确认不一致、重名注册均被拒绝。
2. 正确注册进入新手建角；错误密码不能进入游戏，界面可以重试。
3. 同一账号在 Android、iOS、Web 先后登录，角色名、卡牌和背包保持一致。
4. 关闭客户端后重新打开可自动登录；服务端重启后本机保存的凭证仍可恢复。
5. A 切换到 B，B 显示独立角色；切回 A 仍有原进度；取消输入不会进入旧账号。
6. 凭证被撤销、过期和服务端未启动时均不能绕过校验；恢复网络后可重试。
7. 首次升级只清理未绑定游客，生成完整备份和完成记录；第二次启动不重复清理。
8. 局域网 Web、HTTPS Web 和 iOS 邀请码入口分别确认注册/登录，日志中没有密码或完整凭证。

## 2. 如何更新现有部署

在仓库根目录依次操作：

```powershell
.\停止服务.cmd
git pull --ff-only
.\启动服务.cmd
```

这次更新需要先停止游戏服。对仍运行的服务再次点击启动，只会提示更新待应用，不会中途替换内存中的模板。

启动入口新增以下处理：

1. 比较服务端补丁源码和名称表的指纹；需要更新时，使用已有部署下载的 JDK 8 编译小型服务端补丁及管理工具名称资源。这一步在你执行启动命令时运行，本次没有代为执行。
2. 生成的补丁保存在 `runtime/server/private/server-overlay`，不覆盖仓库中的预编译 JAR、管理 EXE 或源码。
3. 检查新增 ID 是否与运行目录的自定义配置冲突。发现同 ID 内容不一致会停止启动，要求人工合并。
4. 仅向运行目录合并本批新增模板、资源表和图片，升级配套字库，更新资源清单及版本，保留服务器地址、端口和其他已有配置。
5. 将修改前的文件保存在 `runtime/server/private/catalog-backups/<发布指纹前16位>`，然后启动服务。数据库不重新导入，玩家存档不改写。

默认资源版本升为 **`1.78.7`**；已有部署如果使用更高版本则保留更高版本。以 `runtime/server/client-config/deployment.json` 中的值为准。若你使用自定义运行目录，上述 `runtime/server` 对应替换为该目录。

首次成功应用时会显示类似 `Applied basic content catalog: 44 cards, 29 equipment, 9 skills`。运行目录的 `private/catalog-v330.json` 保存发布指纹；重复启动不会重复追加模板。

如果补丁编译失败，启动会终止，详情在 `runtime/server/logs/deployment.log`。可由你手工生成同一补丁：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\deployment\Build-Admin.ps1 -ServerOnly -OutputDir runtime/server/private/server-overlay
```

该命令需要已经部署过的便携 Python 和 JDK 8。若使用其他运行目录，还需传入 `-JavaHome <运行目录>/runtimes/java`。

## 3. 客户端如何取得新增资源

Android、iOS、Web 均从同一个 `resources/client` 目录取资源，本批不需要三套内容实现。按 [客户端打包流程](../CLIENT_BUILD.md) 或 [Web 构建流程](../WEB_CLIENT.md) 重新生成对应客户端，资源版本填写部署输出的值。

- Android：运行现有 `deployment/build-android.cmd`，雷电模拟器继续选对应的 x86 专用包。
- iOS：从更新后的分支发起 Actions 构建；仍需原有签名安装流程。
- Web：重新运行 `deployment/build-web.cmd`，把新的 `outputs/web` 用于网页部署。旧的 `game.data` 不会因为服务端模板更新而自动变成新包。

原生客户端沿用现有热更新机制；如果资源仍来自旧缓存，应先完全退出后再进入并完成资源更新。本次没有验证旧包跨版本更新，重新打包是本批的明确使用路径。服务端和客户端资源必须成套更新。

## 4. 如何获得新增卡牌、装备和奥义

服务启动成功后打开现有 `NRB游戏管理.exe` 并重新登录，管理接口会从当前 XML 和更新后的名称资源生成目录。可按本页 CSV 的名称或模板 ID 查找，指定游戏名发放，或使用原有全服发放功能。

本批的明确获取入口是管理工具传书奖励，**没有修改普通招募池、商店概率和关卡掉落**。新增卡牌重复领取后的影子转换、装备强化和奥义升级仍沿用旧规则。

建议由你编译后按顺序检查：

- 给测试角色发一张罗杰、一张白星或萨博，领取后查看卡面、上阵并升一级。
- 发海皇三叉戟或阎魔，穿戴后查看属性，再强化一级。
- 发寒冰护盾、融合、草帽约定各一本，装上后查看相应防御、攻击、意志变化。
- 配齐一组有效人物缘分和一组有效装备缘分，切换阵容确认激活状态和属性变化，再进入普通远航战斗。

这些是待执行项目，不是已经通过的实测结果。

## 5. 缘分转换和已知边界

旧卡牌的缘分 ID `1～688` 保留。导入卡牌使用的 252 条定义重新分配到 **`689～940`**，两端一致映射，避免新版同 ID 不同数值覆盖原卡牌。

44 张卡的第 7～10 缘分槽均为零，全部有效条件可以放入旧版六槽，未丢弃有效槽位。服务端新增 `FateRequirement` 解析器：

- `_` 表示每个组都要满足。
- `#` 表示组内任选一种模板，例如 `41#210`。
- 人物仍只检查上阵成员，装备仍只检查该成员已穿装备，奥义仍只检查原逻辑涵盖的已带奥义。
- 非法或缺失条件不会激活，也不会因整数解析错误导致游戏请求异常。

## 6. 维护入口和资源兼容处理

| 位置 | 用途 |
|---|---|
| `resources/catalog/v330.json` | 本批两端增量、成长、缘分映射、资源哈希、待补资料和兼容处理记录 |
| `resources/client/{Disciples,Equips,Skills,Yuanfens}.txt` | 实际发布表，保持原项目压缩格式 |
| `archive/client-resources/` 下同名四表 | 对应的可编辑明文资料 |
| `resources/client/ported/v330/` | 192 个独立图片和音效文件，约 8.4 MB；避免覆盖旧角色图片 |
| `resources/client/Lang/heiOutline24*` | APK 的扩展字库及配套图集，保留全部旧字和原字形尺寸，补充戟、弑、忤、砥等字符 |
| `server/config/xml/{disciple,equip,skill,fate}.xml` | 新部署的服务端模板源 |
| `server/source/src/com/oldmountain/dzm/util/FateRequirement.java` | 缘分条件解析 |
| `deployment/catalog_update.py` | 对已部署运行目录执行增量更新和备份 |
| `deployment/admin/source_inputs.py` | 选择补丁源码并计算指纹 |
| `scripts/import_apk_catalog.py` | 从固定 APK 资源重新生成本批配置；不参与常规启动 |

已处理克力架战斗图大小写和勇治、伊治重复 `.mp3` 后缀。卡牌、装备和奥义的名称沿用本地文字标签；缺失且已隐藏的名称贴图字段使用对应卡面作安全引用。两套字库均缺“鹫”，格里芬的说明将“狮鹫”写为同义的“狮身鹰首兽”，数值保持源表内容。

需要重新执行数据导入时，提供审计 APK 的解压目录：

```powershell
python scripts/import_apk_catalog.py --assets outputs/apk-analysis/xy1lule2eb176/extracted/assets
```

导入器校对固定源表哈希，拒绝使用线上更新或被改动的源表；遇到本地同 ID 不同内容也会拒绝覆盖。正常克隆、部署和打包只使用已提交的模板与资源，不需要原 APK 或反编译工具。

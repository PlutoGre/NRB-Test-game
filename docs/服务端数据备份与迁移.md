# 服务端数据备份与迁移

本说明适用于本仓库一键部署的服务端，包含日常备份、在新 Windows 电脑或云服务器恢复、迁移后的客户端连接处理。命令均在**项目根目录的 PowerShell** 执行，路径相对于当前项目，不需要固定盘符。

本次只编写说明，没有执行停服、备份、恢复、数据库迁移或客户端构建。

## 一、哪些数据需要备份

默认运行目录为 `runtime/server`。如果部署时指定了其他 `-InstallDir`，下文命令和路径也要使用相同参数。

| 数据 | 保存位置 | 数据库备份是否包含 |
|---|---|---|
| 注册账号、密码摘要 | `dzm.nrb_accounts` | 包含；新版账号服务启动后创建此表 |
| 登录会话 | `dzm.nrb_account_sessions` | 包含；客户端保存的凭证仍受有效期限制 |
| 账号与角色的关联 | `dzm.mapping` | 包含 |
| 角色、钻石、金币、卡牌、装备、奥义、背包、玩法进度 | `dzm` 中的 `player`、`disciple`、`equip`、`skill`、`bag` 等表 | 包含已经落库的数据 |
| 游戏统计 | `dzm_stat` | 包含 |
| 手工修改的服务端 XML、JAR | `runtime/server/server` 中的对应文件 | 不包含，需另行保存 |
| 手工修改的公开资源和连接配置 | `runtime/server/web`、`runtime/server/client-config` | 不包含，需另行保存或由同版本源码重新生成 |
| 客户端签名文件、证书、私钥 | 自行保管的位置 | 不包含，需单独保管 |

`runtime/server/dbdata` 是 MariaDB 的物理数据目录。迁移使用下面的逻辑备份，不直接复制运行中的数据库目录。只复制源码、初始 `server/database/dzm.sql` 或单独一张账号表，不能完整迁移账号和角色。

## 二、备份前先确认进度已经保存

部分玩法先修改 Java 内存中的玩家对象，再由定时任务写入数据库。当前停止脚本会强制结束游戏进程，**不能把“停止服务”理解为“立即保存全部内存进度”**。

维护前先结束玩家操作，留出正常落库时间；重要迁移应结合服务端保存日志及数据库记录，确认最近的角色进度、装备和背包已经写入。仅退出手机游戏、关闭命令窗口或看到界面上的新数值，都不能代替落库确认。

保存机制和当前停服边界见 [服务端数据保存说明](extension/01_服务端数据保存与奖励发放.md)。下列备份保存的是数据库中已有的数据，不能恢复停服时尚未落库的修改。

## 三、在旧服务器生成备份

### 1. 完整停止本实例

确认数据保存后，在项目根目录双击 `停止服务.cmd`，或执行：

```powershell
.\停止服务.cmd
```

该入口会停止本实例拥有的游戏、资源服务、网页入口和隧道。停止命令完成后，再运行备份。不要让旧服务器在导出后继续接收玩家操作，否则这些后续进度不会出现在已经生成的备份里。

### 2. 执行备份

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\deployment\Deploy-Server.ps1 -Action backup
```

脚本会按需启动本实例的数据库，导出 `dzm` 和 `dzm_stat`，生成压缩备份及 SHA-256 校验文件。完成后数据库可能仍在运行，游戏和外网入口保持停止。

输出示例：

```text
runtime/server/backups/onepiece-实际时间.sql.gz
runtime/server/backups/onepiece-实际时间.sql.gz.sha256
```

以窗口实际输出的文件名为准，**两个文件必须一起保存和复制**。保留文件名对应关系，不要只改其中一个文件名。备份包含账号及角色资料，应存放在自己控制的位置，不上传到公开 GitHub 仓库或公开网页目录。

### 3. 备份后如何处理旧服

- 只是日常备份：完成后按需运行 `启动服务.cmd`，恢复原来的开服方式。
- 准备正式迁移：旧服保持停止，直到新服务器恢复并核对完成，避免两边分别产生不同进度。

## 四、在新 Windows 电脑或云服务器恢复

### 1. 取得同一版本项目并初始化

在任意有写权限的目录 clone 仓库，尽量使用旧服务器对应的代码和资源版本，先双击 `启动服务.cmd` 完成首次部署，再双击 `停止服务.cmd`。

新服务器首次部署得到的是初始库；旧账号和角色要在下一步恢复后才会出现。首次部署的账号升级流程会按本项目已有设置处理未绑定的测试游客，不能把旧游客备份当成已注册账号存档。

### 2. 复制备份及校验文件

创建迁移目录：

```powershell
New-Item -ItemType Directory -Force .\runtime\server\backups\incoming
```

把旧服务器生成的 `.sql.gz` 和配套 `.sql.gz.sha256` 都复制到这个目录。另行保留手工修改的 XML、JAR、资源及签名资料；新服务器的数据库连接配置由新部署生成，不要直接用旧服务器的整套 `private` 目录覆盖。

### 3. 执行恢复

将下面的“实际时间”替换为复制过来的备份文件名：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\deployment\Deploy-Server.ps1 -Action restore -RestoreFile .\runtime\server\backups\incoming\onepiece-实际时间.sql.gz -ConfirmRestore
```

恢复会替换目标库中备份所包含的游戏数据。脚本先检查配套校验文件，再自动备份目标数据库，然后导入旧服务器的数据库。游戏及网页进程必须保持停止；`-ConfirmRestore` 是恢复命令的必要参数。

如果恢复中断，会留下 `runtime/server/private/restore-in-progress` 标记并阻止启动。查看部署错误和日志，解决原因后重新完成恢复；不要删除标记后直接当作恢复成功开服。

### 4. 启动并核对

```powershell
.\启动服务.cmd
```

恢复完成后，根据原来的开服方式启动局域网、网页或外网入口。使用原账号密码登录，核对角色名、等级、钻石、卡牌、装备、背包及重要玩法进度。账号、角色关联和角色数据应一起迁移，不要手工重建同名账号代替恢复旧账号表。

核对完成后再向玩家提供新入口，并继续保留旧服务器和原备份一段时间。

## 五、服务器地址变化后，客户端怎么办

| 客户端 | 操作 |
|---|---|
| Web | 打开新服务器提供的网址；新网址可能要求重新输入原账号密码 |
| iOS 外网连接模式 | 使用新服务器的 HTTPS 地址和对应邀请码，再以原游戏账号登录 |
| Android 或 iOS 局域网包 | 使用新服务器的地址、端口生成连接配置；地址写在旧包中时，按构建文档重新打包安装 |

数据库中的账号 UID 和角色关联不依赖设备或网址。完整恢复新版账号数据库后，换设备或换入口仍可使用原账号密码找到角色。仅改变域名或 IP 不会自动把旧客户端的连接地址改到新服务器。

客户端步骤见 [客户端打包流程](客户端打包流程.md)，网页入口见 [网页客户端说明](网页客户端流程.md)，账号结构见 [游戏账号体系](extension/09_游戏账号体系.md)。

## 六、自定义运行目录

如果原部署不在默认的 `runtime/server`，备份和恢复命令都显式指定实际运行目录。例如，项目下的另一运行目录为 `runtime/my-server`：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\deployment\Deploy-Server.ps1 -Action stop -InstallDir .\runtime\my-server
powershell -NoProfile -ExecutionPolicy Bypass -File .\deployment\Deploy-Server.ps1 -Action backup -InstallDir .\runtime\my-server
```

新服务器恢复时也传入它自己的实际 `-InstallDir`。相对路径统一以项目根目录为基准，不要求新旧电脑的盘符或项目位置相同。

## 七、迁移到 Ubuntu 或其他 Linux 服务器

数据库导出是 SQL 逻辑备份，不绑定 Windows 盘符；其中的 `dzm`、`dzm_stat` 和账号角色表可以在兼容的 MariaDB 环境中导入。

当前一键部署、进程管理及便携运行时使用 Windows 实现，不能将上述 PowerShell 流程直接视为 Linux 一键部署。Linux 目标还需要准备数据库、Java、游戏配置、资源服务及对应网关，并重新生成数据库连接和公开入口配置。数据库迁移与 Linux 部署适配是两件事，不能只复制 Windows 的运行时目录完成迁移。

更多历史迁移方式和故障排查见 [服务端部署参考](reference/服务端部署与迁移参考.md)。

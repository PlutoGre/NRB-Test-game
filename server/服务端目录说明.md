# 服务端

日常启动和停止仍使用仓库根目录的 `启动服务.cmd`、`停止服务.cmd`，不要从源码目录直接运行历史启动批处理。

| 目录 | 用途 |
|---|---|
| `source/src` | Java 游戏逻辑、实体、协议、玩法、持久化和管理接口 |
| `source/lib` | 原工程的 Java 依赖 |
| `source` | 原 Java 工程的 Ant/IDE 配置；内部 `src` 和 `lib` 的关系保留 |
| `config/xml` | 游戏服配置、卡牌、装备、技能和活动模板 |
| `config/hibernateconfig` | 部署时使用的 Hibernate 配置模板 |
| `distribution/DZM.jar` | 一键部署使用的基础服务端发布包 |
| `database/dzm.sql` | 一键部署的新游戏库初始数据 |
| `database/dzm_stat.sql` | 一键部署的统计库初始数据 |
| `database/legacy` | 历史 SQL、旧快照与变更脚本，不自动导入 |

部署程序将发布包和配置复制到 `runtime/server/server`，再写入当前电脑的地址、端口和数据库参数。玩家进度保存在运行目录的数据库中，不能通过修改初始 SQL 更新已运行的数据库。

修改 Java 源码后，需要自行构建并更新对应发布包；迁移目录不等于已经重新生成 JAR。管理模块的源码入口已同步到新目录，构建说明见 [管理工具](../docs/游戏管理工具.md)。原 Ant 工程输出的 `source/dist/lib/DZM.jar` 与 `distribution/DZM.jar` 仍需由维护者在构建验证后进行发布同步。

历史 PHP 运营后台、导表工具源码和旧启动脚本位于 [`archive/server`](../archive/server)。数据修改和奖励发放见 [服务端扩展指南](../docs/extension/01_服务端数据保存与奖励发放.md)。
